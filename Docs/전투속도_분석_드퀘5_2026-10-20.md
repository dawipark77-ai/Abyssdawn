## 2. 드퀘5 한 행동의 박자 구조 (관찰 — 초 수치는 추측)

드퀘 전투의 핵심은 **한 행동 = 두 박자**다.

```
① 선언   "파파스의 공격!"            ← 줄이 뜨고 짧게 멈춤      (추측 0.3~0.5초, 기본 속도)
② 연출   적 깜빡임 / 화면 흔들림 + 효과음                       (추측 0.2~0.3초)
③ 결과   "슬라임에게 12의 데미지!"    ← 읽을 시간만큼 멈춤        (추측 0.5~0.8초)
④ (쓰러뜨리면) "슬라임을 쓰러뜨렸다!" ← 한 줄 더
```

- 한 행동 합계: 기본 속도 약 1.0~1.6초, 최고속 약 0.5~0.8초 (**추측**).
- 3~4명 + 적 3마리면 한 라운드 7행동 → 기본 약 8~11초, 최고속 약 4~5초 (**추측**).
- 플레이어가 버튼을 누르면 남은 대기를 건너뛰어 다음 줄로 넘어간다. 그래서 "느리지만 답답하지 않은" 느낌이 난다.
- 아군이 맞으면 화면 흔들림, 적이 맞으면 적 그림 깜빡임 — **그림 쪽 연출은 매우 짧고**, 시간은 대부분 글 읽는 데 쓴다.

## 3. 아비스던 현재 구조 (코드 실측)

| 값 | 위치 | 현재 |
|---|---|---|
| `actionDelay` (행동 시작 전 대기) | BattleManager 씬 값 | 0.5초 |
| `turnDelay` (행동 끝난 뒤 대기) | BattleManager 씬 값 (`Abyysborn_Battle 01`) | 0.3초 (코드 기본 1.0) |
| `BattleFxCombat.LungeLead` (튀어나옴) | BattleFxCombat.cs | 0.12초 |
| 베기 프레임 | `StabFrameTime` 0.075 × 프레임 수 | 약 0.5초 |
| 연타 사이 | 0.3초 / 이중타격 0.28~0.4초 | |
| 전투 로그 | `AddMessage` — **타이핑 없이 한 번에** 뜸 | |
| 순차 메시지(승리·레벨업 등) | `SequenceRoutine` — 글자당 0.04초 + 줄마다 클릭 대기 | |

- 한 행동 ≈ 0.5 + 연출(0.1~0.6) + 0.3 → **약 0.9~1.4초**. 드퀘 기본 속도와 거의 같은 길이.
- 차이점은 길이가 아니라 **박자**다.
  1. 선언과 결과가 한 줄(또는 같은 순간)에 같이 뜬다 → "누가 무엇을 했나"를 읽기 전에 결과가 보인다.
  2. 대기 시간이 **고정**이다 → 클릭해도 빨라지지 않는다 (해결 단계에서 건너뛰기 입력 없음).
  3. 속도 설정이 없다.

## 4. 제안 (승인 대기 — 아직 적용 안 함)

| 번호 | 내용 | 난이도 |
|---|---|---|
| A | **전투 속도 설정 1~5단계** — `actionDelay`·`turnDelay`·연출 시간에 배율 (예: 1=×0.4, 2=×0.6, 3=×0.8 기본, 4=×1.0, 5=×1.3). 저장 파일에 기록 | 낮음 |
| B | **두 박자 로그** — "Hero의 베기!" 먼저 → 연출 → "쥐에게 12의 피해!" | 중간 (공격 경로마다 AddMessage 순서 정리) |
| C | **누르면 빨라짐** — 해결 단계에서 클릭/키를 누르고 있는 동안 대기 시간 ×0.3 | 낮음 |
| D | 쓰러뜨림 줄을 따로 — "쥐를 쓰러뜨렸다!" 한 줄 + 짧은 멈춤 | 낮음 |

추천 순서: **C → A → D → B**. C와 A만으로도 "답답함" 문제는 대부분 풀린다 (**추측**). B는 손이 많이 가므로 마지막.
